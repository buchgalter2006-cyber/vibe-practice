# PLAN.md — каркас сервиса отчётности (Ф3)

> План написан в сессии-планировании 23.09.2026 и реализуется **в отдельной сессии** (правило курса М6: «план в файл → реализация в новой сессии», PLAN.md — источник правды для исполнителя).
> Источник дизайна: `mockup/index.html` (принят Дмитрием, фаза 2). Тестовые данные: `data/mock_data.json` (+ CSV там же).

## 1. Что делаем

Приложение-сервис отчётности: Flask-сервер отдаёт статику (переносим макет) и JSON API с данными; настройки и нормативы хранятся в SQLite. Данные пока берутся из тестового датасета **через слой источников** — чтобы на фазе 4 подменить источник на Google-таблицу / Excel / API, не переписывая приложение.

**Ничего реального не подключаем** (это Ф4), **никуда не деплоим** (это Ф6).

## 2. Стек и почему (отличие от курса)

| В курсе | У нас | Причина |
|---|---|---|
| Node.js + Postgres | **Python 3.9 + Flask + SQLite** | на машине нет Node/npm/Homebrew; Python 3.9 есть из коробки, SQLite встроен в стандартную библиотеку |
| npm-пакеты | pip + venv (`.venv`) | изоляция зависимостей |
| ORM | прямые запросы `sqlite3` | минимум зависимостей, читаемость |

Ограничение: Python 3.9 — **без** синтаксиса `match`, без `X | Y` в аннотациях (использовать `typing.Optional`, `typing.List`), без `dict[str, int]` в рантайме.

## 4. API (контракт)

Все ответы — JSON, кодировка UTF-8, числа как числа (не строки). Ошибки: `{"error": "..."}` + HTTP-код.

| Метод | Путь | Что отдаёт |
|---|---|---|
| GET | `/api/meta` | компания, валюта, ставка НДС, список месяцев, признак неполного месяца |
| GET | `/api/overview?period=all\|q3\|sep` | поступления/списания по месяцам (с НДС), остаток, структура расходов, последние операции |
| GET | `/api/marketing?period=...` | план/факт по каналам и месяцам, освоение, отклонение |
| GET | `/api/sales` | воронка, направления, выручка/сделки/конверсия/средний чек |
| GET | `/api/metrics?period=...` | 4 метрики: значение, норматив, отклонение, формула; всё без НДС |
| GET | `/api/settings` | настройки (ключи маскировать: показывать только факт наличия) |
| PUT | `/api/settings` | сохранить настройки (ключи, ссылки, нормативы) |

Параметр `period` фильтрует месячные ряды; метрики пересчитываются от периода (ROAS, Cash Conversion), CAC и валовая прибыль на лида — от периода целиком (в данных нет разбивки сделок по месяцам — так и указать в ответе флагом `basis`).

## 6. Настройки и SQLite

`app/db.py` — при первом запуске создаёт `data/app.db`:

```sql
CREATE TABLE IF NOT EXISTS settings (
  key TEXT PRIMARY KEY, value TEXT, updated_at TEXT
);
CREATE TABLE IF NOT EXISTS norms (        -- нормативы метрик (вкладка «Метрики»)
  metric_key TEXT PRIMARY KEY, norm_value REAL, unit TEXT, good_is_higher INTEGER
);
CREATE TABLE IF NOT EXISTS import_log (   -- журнал импортов (пригодится в Ф4)
  id INTEGER PRIMARY KEY AUTOINCREMENT, source TEXT, started_at TEXT, finished_at TEXT,
  rows_imported INTEGER, status TEXT, message TEXT
);
```

- Нормативы при первом запуске засеять из `mock_data.json` (`metrics[].norm`).
- Настройки-примеры (пустые): `google_sheet_url`, `excel_path`, `fintablo_token`, `bitrix_webhook_url`.
- `GET /api/settings` **не отдаёт секреты целиком**: только `{"fintablo_token": {"set": true, "hint": "••••1234"}}`.

3. Переключатель периода — дергать API с `?period=`, а не фильтровать на клиенте.
4. Вкладка **Настройки** (сейчас заглушка) — рабочая форма: поля `google_sheet_url`, `excel_path`, `fintablo_token`, `bitrix_webhook_url`, нормативы 4 метрик; GET при открытии, PUT по кнопке «Сохранить», показывать статус.
5. Полоса загрузки/ошибка API — простой индикатор «Загрузка…» / «Сервер недоступен».

## 8. Запуск

```bash
cd ~/Projects/vibe-practice
.venv/bin/python app/server.py            # http://127.0.0.1:5000
```

- `server.py`: `Flask(__name__, static_folder="static", static_url_path="")`, host `127.0.0.1`, port из `.env` (`PORT`, по умолчанию 5000), `debug=True` для локальной разработки.
- `.env.example`:
